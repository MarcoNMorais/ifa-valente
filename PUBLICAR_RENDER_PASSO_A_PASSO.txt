PUBLICAR NO MESMO GITHUB E NO MESMO RENDER — SEM CRIAR OUTRO PLANO

Este pacote foi preparado para atualizar o repositório e o serviço que já
existem. Não crie novo repositório, Blueprint, Web Service ou Persistent Disk.

ANTES DE ENVIAR

1. Baixe um backup do IFA.
2. Baixe um backup do CIS.
3. Baixe/exporte os dados do Estoque Hospitalar.
4. No Render, confirme que o disco atual está montado em /var/data.
5. Não exclua nem recrie o serviço atual.

GITHUB — ATUALIZAR O REPOSITÓRIO EXISTENTE

1. Extraia o ZIP entregue.
2. Abra no GitHub o mesmo repositório que já publica secsaudevalente.com.br.
3. Entre na raiz do repositório.
4. Clique em Add file > Upload files.
5. Arraste o conteúdo de dentro da pasta extraída, e não a pasta por fora.
6. Aceite substituir os arquivos com o mesmo nome.
7. Confirme que também foram enviados:
   - Cemes/
   - CemesExtensao/
   - docs/CEMES/
   - cemes_routes.py
   - server.py
   - render.yaml
   - requirements.txt
8. Use a mensagem: CEMES integrado ao mesmo serviço.
9. Clique em Commit changes.

RENDER — USAR O SERVIÇO ATUAL

1. Abra o serviço atual ifa-valente.
2. Não clique em New, Blueprint ou New Web Service.
3. Em Settings, mantenha:

   Build Command:
   pip install -r requirements.txt

   Start Command:
   gunicorn server:app --bind 0.0.0.0:$PORT --workers 1 --threads 8 --timeout 120

   Variável:
   IFA_DATA_DIR=/var/data

   Disco:
   mountPath=/var/data

4. Não troque o nome, o caminho ou o disco persistente.
5. Abra Manual Deploy > Deploy latest commit.
6. Aguarde o status Live.

POR QUE OS DADOS ANTIGOS NÃO SÃO SOBRESCRITOS

- IFA continua em /var/data/ifa_valente.db.
- CIS continua em /var/data/cis/cis_database.json.
- CEMES cria /var/data/cemes/cmvr.db.
- Os backups do CEMES ficam em /var/data/cemes/backups.
- O deploy atualiza o código; o Persistent Disk continua anexado.

TESTE DEPOIS DO DEPLOY

1. Abra https://secsaudevalente.com.br/
2. Confirme os quatro botões.
3. Teste:
   - https://secsaudevalente.com.br/ifa
   - https://secsaudevalente.com.br/CIS
   - https://secsaudevalente.com.br/EstoqueHospital
   - https://secsaudevalente.com.br/Cemes
4. Abra https://secsaudevalente.com.br/Cemes/api/health
5. Confirme que aparece "status": "ok".
6. Entre no CEMES, distribua uma agenda pequena e gere um backup.
7. Faça novo Deploy latest commit e confirme que a agenda permanece.

SE O DEPLOY NÃO ABRIR

1. Leia a primeira mensagem vermelha em Logs.
2. Confirme que o Start Command usa server:app, e não app:app.
3. Em Events, use Rollback para a versão anterior.
4. Não apague nem restaure o disco.
